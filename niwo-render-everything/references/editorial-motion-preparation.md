# 横屏信息动效版备料

仅当用户明确选择 `landscape-editorial-motion-v1` 时使用本节。普通横屏、竖屏视频和竖屏信息版沿用原流程。`editorial.prepared_for` 只说明素材面向哪个版面；用户仍需在 Niwo 渲染界面选择该版面。

本节只规定外部 Agent 如何备料。标题、卡片、图解、视频窗口和同屏布局由 Niwo 编排生成；不要为了实现这些成片效果，将新文字、卡片、软件截图或动效提前合进视频底片。视频、真实界面图片与视频派生透明前景分别交付。

## 按定稿口播找画面

所有视频底片必须为横屏；打包前用 `ffprobe` 核对显示宽高，并运行 `validate_bundle.py --layout landscape-editorial-motion-v1`。

把用户已确认的 `script` 按叙事意思分段，给每段稳定的 `id`、原文连续摘录 `script_anchor`、叙事角色 `role` 和可见的画面目标 `visual_goal`。片名另填 `title_text`，用 `title_anchor` 指向文案原文。不要修改口播来迁就素材；分段只存在于备料说明中。

逐段搜索、下载与画面目标直接相关的真实视频，按对应口播的估算时长准备足够的**不同视频**，逐段核对主体、语义和可用窗口，不能把一个段落的富余时长拿来掩盖另一段缺片。同一原片的重复下载、改名或相同画面的不同裁切不能算新视频，也不能重复累计容量；素材用途和段落关联交给 Niwo 作为编排参考，不在备料阶段确定成片中的视频窗口、图解布局或两者的可见时长占比。

素材可以裁成短片，也可以在 manifest 标出有效选段。通过 `ffprobe` 核对每段实际时长，只累计可用窗口：裁好的片段算完整时长，长原片算 `clip_end_seconds - clip_start_seconds`，只写起点时算到原片结尾。让不重复视频的可用窗口总和至少达到目标时长的 90%；有实测配音时长后，改用实测值复核。90% 是备料容量下限，不是成片中的视频占比；不能靠慢放、冻结、循环或静态图片补足。最终视频、图解和纯文字画面的安排由 Niwo 按内容决定，不预设固定占比。

另从**包内已声明的真实视频**抽一帧并抠出人物或物体主体，至少交一张带透明区域且主体可见的 PNG 前景。`derived_from.file` 精确指向该视频，`at_seconds` 是在该文件内的抽帧秒数；如文件已裁过，按裁后文件从零计时。`focus` 可记录源画面的主体框，用 0 到 1 的相对坐标，供说明构图使用；当前纸面编排不据此对实景物体画圈、引线或跟踪标注。前景 PNG 是视频派生的叠层，不计入视频时长。普通截图、图表和参考图片使用 `reference_image`，不声明 derived_from，不要求透明，也不计入视频时长；不能标作 `foreground`。

## 备料元数据

`content.json` 增加 `editorial`，段落字段见 [content 协议](content-schema.md#editorial)。每个新横屏素材在 `manifest.json` 的条目中增加 `editorial`；视频底片标 `footage`，透明 PNG 叠层标 `foreground`，普通截图标 `reference_image`，字段见 [manifest 协议](manifest-schema.md#editorial)。`segment_ids` 引用已声明的段落编号；`title_candidate` 只提示该素材可作片名镜头，`subject` 和 `focus` 说明主体与构图。元数据负责传达素材用途，不是完整分镜，也不保证最终画面一定采用该素材。

这个版面的 `images/` 和 `videos/` 中不要留未写进 manifest 的文件；新增或删除素材后要同步修改清单并重新校验。

5 分钟片子需要较长的有效视频窗口，但 Niwo 浏览器上传只接收最多 100 个媒体文件、最大 200 MiB 的 ZIP。先裁掉无用片段，再用合适的分辨率和码率压缩视频；不要通过慢放、冻结或重复选段凑时长。新横屏本地校验器按 `images/`、`videos/` 的实际文件数检查 100 个上限，并保守地把素材包目录内所有文件的原始字节合计限制在 195 MiB，为 ZIP 文件头和目录留出余量。打包前清理不需要的文件，打包后再核对最终 ZIP 不超过 200 MiB。所有版面统一遵守相同上传容量限制。

## 验收

运行 `validate_bundle.py` 时必须给 `--target-seconds` 或 `--narration-seconds`。后一项有值时优先采用。校验器核对 JSON 结构、原文锚点、段落关联、视频文件和选段、PNG 透明度、包内视频来源与抽帧位置，并计算 90% 的备料容量。还需人工检查不同文件是否为同一视频、视频主体、段落语义和抠图边缘，抽查交付视频未被 Agent 新增标题、卡片、界面或动效包装。校验器不识别视频中是否新增了 UI，也不验收最终成片的画面占比；文件通过校验不代表已完成这两项视觉检查。成片的排版与动效由 Niwo 渲染后另行检查。
