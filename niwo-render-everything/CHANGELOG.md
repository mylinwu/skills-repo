# 更新记录

版本号写在同目录的 `version.json`，Skill 每次开工前会拿它跟公开仓库上的那份比对。

改动规则：动过这个目录里的任何文件，就要同时改 `version.json` 的 `version`，并在这里补一条。
Niwo 服务端协议变了、旧版产出的素材包会被拒收时，把 `min_compatible` 抬到新版本号，
用户那边就会收到「必须更新」而不是「可以更新」。

## 1.2.0 — 2026-10-23

- 新增由 Niwo 提交模型导出的 JSON Schema；检查标签、相关度、顶层说明等此前漏检字段，所有版面统一验收100媒体和上传体积。
- 新增 `reference_image`，普通截图无需伪造透明度或来源视频；Niwo、编排端和 Skill 同步支持。
- 新增 `--json` 修复报告与 `pack_bundle.py`，先验证副本，再复检最终ZIP，通过后才发布交付路径及SHA-256。
- 校验失败交由外部Agent自主修复和复检，不直接结束任务；只有真实缺失信息或需要改变需求时才找用户。
- 发布顺序：先部署支持新角色的编排端与Niwo后端/前端，再发布Skill。升级最低兼容版本，避免旧校验脚本继续漏检。

## 1.1.3 — 2026-10-16

- 明确所有版面的外部 Agent 只负责文案与素材准备，新增标题、卡片、图解、界面叠层及动效由 Niwo 生成，不提前合入实拍底片。
- 澄清 `title_text`、`visual_goal` 与 `title_candidate` 只传达内容和用途；真实界面图片与视频派生透明前景独立交付。
- 删除横屏信息动效版备料说明中的固定成片视频与 UI 占比，保留 90% 有效视频备料容量下限，并区分脚本校验与人工画面检查。
- 本次调整备料指导，不修改服务端字段协议或最低兼容版本。

## 1.1.2 — 2026-10-10

- 三种横屏版面逐条验收视频显示宽高，竖屏素材或无法读取方向时停止打包。
- 普通横屏和横屏纯视频版在 `content.json` 中声明备料目标，供 Niwo 推荐版面；旧包无需增加字段。
- 修正横屏纯视频版已接入工作台后的说明。

## 1.1.1 — 2026-09-25

- 新横屏素材包打包前检查媒体文件不超过 100 个，原始待打包文件不超过 195 MiB，并提示核对最终 ZIP 的 200 MiB 上传上限；普通版面不变。

## 1.1.0 — 2026-09-25

- 在成片形态选择中明确列出横屏信息动效版；定稿前按看点、片名和起因组织长片文案，并与用户一起确认片名。
- 增加横屏信息动效版专属备料说明：按定稿口播分段搜真实视频，备足目标或实测口播时长至少 90% 的有效视频窗口，并从包内视频制作透明前景 PNG。
- 为 `content.json` 和 `manifest.json` 补充可选 `editorial` 字段协议；备料意图不替用户选择渲染版面。
- 本地校验器检查新横屏的原文锚点、段落与素材关联、视频容量、前景透明度和包内视频来源。其他版面沿用原校验路径。
- 新版面要求包内每个视频和图片都在清单中声明用途；缺失、漏标或多余的文件会阻止导入。

## 1.0.1 — 2026-09-11

- 含阿拉伯数字（含全角形式）的原文词条整条跳过注音，不通过部分注音、改写数字或直接插入音素标签绕过规则，降低数字与音素标签混用的兼容性风险。
- 明确限制针对原文词条，不限制拼音值中的声调数字；同句中其他不含数字、确实需要纠音的独立词条仍可标注。

## 1.0.0 — 2026-09-04

- 加上版本号与 `scripts/skill_update.py`：开工前检查有没有新版，可以就地更新到最新。
